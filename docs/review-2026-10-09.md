# Implementation follow-up review, 9 October 2026

This records the hardening checkpoint. Later on the same day, [Phase 6](phase-6.md)
delivered the evidence-correction flow and offline evaluation harness; its review
updates the status of those items below and records 241 passing tests.

Verdict: the four confirmed defects from the 8 October review are fixed in the
tracked backend, with regression coverage. Proceed with a small staging platform
integration and human-scored AI evaluation. Production readiness still depends on
identity/offer contracts, operational measurements, retention and delivery rules.

Scope: request transport, CV/draft admission, parser and leased-worker failures,
reference checkout integrity, API/persistence regressions and runtime image. This
is a focused follow-up, not a new comprehensive security audit or live AI-quality
evaluation. The temporary Streamlit launcher is outside the delivered backend.

## Original findings and disposition

| Finding | Change | Evidence |
| --- | --- | --- |
| P1: JSON buffering before authentication was unbounded | `app/http_limits.py` adds ASGI limits before FastAPI parsing: 256 KiB ordinary bodies, 5 MiB PDF uploads, a 10-second total read deadline and 16 admitted buffered requests per process. Declared length is checked before reads; actual chunks are counted. | The original 1 MiB unauthenticated probe now returns 413 with zero FastAPI body reads. Tests cover declared and unknown lengths, early rejection, slow reads, concurrent admission, disconnects, separate PDF limits and health checks under saturation. |
| P1: unlimited per-account stored PDFs and queued work | `app/db/admission.py` serializes admission and enqueue in one MongoDB transaction. Default limits: 5 unfinished CV/draft jobs per user, 50 MiB stored PDF bytes, 10 accepted new enqueues per UTC minute and 1000 unfinished jobs globally. | The original 12-upload probe now yields five 202 responses and seven 429 responses, with five files/tasks. Real MongoDB tests exercise concurrent user/global/storage caps, cross-queue accounting, idempotency, existing uploads, deletion, running jobs, terminal failure, rate-window rollover and transaction rollback. |
| P2: parser launch failures terminate the CV worker | Expected process/monitor failures normalize to `cv_parser_unavailable`; the parser boundary retries after 5 seconds up to the configured attempt limit. Programming errors continue to surface. | The original `OSError` probe now leaves a pending retry without an unhandled exception or running lease. Regression tests exhaust attempts, verify no provider call and process the next valid CV with the same worker. Existing lease fencing/history rollback tests still pass. |
| P2: Windows checkout changes download checksums | `.gitattributes` marks all raw reference sources `-text`. Existing expected SHA-256 values and integrity verification are preserved. | Fresh temporary Git checkouts with `core.autocrlf=true` and `false` match every recorded source hash on Windows and in a Linux container. A Windows/Linux CI matrix now runs this regression. |

Admission uses the actual task/import rows as the reservation ledger. Enqueue and
deletion/outcome changes are transactional, so finished/deleted work releases
capacity without separate counters drifting. Retries and expired running leases
retain queue capacity. Failed or accepted imports retain stored bytes until
explicit deletion. Existing rows count immediately after an upgrade.

All API instances sharing a database must use the same admission settings.
Startup initializes the guard/indexes before accepting persistent requests.
The shared guard deliberately serializes admissions; its throughput and contention
still need measurement. The rate limit applies to accepted new CV/draft work;
idempotent replays and other endpoints need perimeter request-rate protection.

The transport cap bounds application buffering, including while downstream work
runs. It does not bound HTTP server/proxy allocations, connection counts or
headers, and its concurrency limit multiplies by API processes. GET health
handlers do not read bodies and bypass buffering admission. Ingress limits remain
part of the deployment gate.

## Remaining limitations and release gates

1. **Platform identity and canonical sources remain unintegrated.** Default user
   routes still fail closed without the trusted verifier. Organization access,
   offer publication/versioning and candidate discoverability are not established
   by the current adapter. Supplied job/company text is not a verified live offer.
   Submission and matching remain disabled.
2. **Semantic support is still a model proposal.** The original unrelated-evidence
   probe still accepts a Kubernetes assessment supported by “Python university
   project”, alongside an invented letter claim. Exact quote occurrence is not
   semantic support or truth. Citation ID validation similarly does not establish
   sentence-level support. Human-labelled evaluations and versioned assessment
   corrections are required. Editing a letter and regenerating after profile
   correction exist; direct evidence-matrix correction is still missing.
3. **Memory and completeness need product-specific evaluation.** Keyword memory
   filtering is not an identity classifier; names may persist. Completeness is
   field presence, not qualification or compatibility. Do not turn these outputs
   into automatic hiring decisions or percentages without validated meaning.
4. **Capacity and worker health are not established by these tests.** Per-user
   caps reduce queue domination but do not implement tenant scheduling fairness.
   Worker supervision is documented; the actual deployment must configure and
   exercise restart/alert behavior. Queue counts are not worker heartbeats.
5. **Total data lifecycle is incomplete.** CV byte admission bounds original PDFs,
   not profile/draft history, conversations, retained extracted text or unconsumed
   outbox events. Retention/account deletion policy, provider data decisions and a
   complete MongoDB backup/restore drill remain required.
6. **Dependency/image assurance remains incomplete.** The previous bounded package
   metadata scan was not a full vulnerability audit. This follow-up did not repeat
   that scan or audit credentials/Git history. Add maintained dependency/container
   scanning to CI. One upstream Starlette/httpx TestClient deprecation remains.

## Verification

The final full suite passed **218 tests** with real disposable MongoDB/Qdrant and
the pinned local embedding model, with one upstream TestClient deprecation
warning and no skips. Ruff lint, formatting and `git diff --check` passed.
Focused verification also passed: 39 admission/CV/checkout tests, followed by 14
admission/transport tests after the final time-window and health-probe adjustments.

The rebuilt `sid-agent:review-2026-10-09` image passes liveness (200) and oversized
unauthenticated JSON rejection (413) as UID 10001 on a read-only filesystem.
Windows and Linux fresh-checkout tests each pass both line-ending settings. Linux
uses a disposable container with the workspace mounted read-only; its minimal
pytest installation reports two expected missing-asyncio-plugin config warnings.
GitHub CI was edited but was not run remotely during this task.

All database tests/probes use synthetic records and isolated disposable databases.
The development MongoDB/Qdrant services were started after Docker was found
stopped; no production database was modified. No Groq/Gemini generation call was
made. Existing local credentials and unrelated user files were preserved.

Reproduction commands and operational defaults are documented in
[`operations.md`](operations.md). The dated probe script/result and container
smoke script are in the ignored `.local-ui` directory; the original review and
its evidence remain available. A copy of this review is placed there too.
